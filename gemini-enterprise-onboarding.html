Another Day of automating infra - Gemini Enterprise Onboarding

If you are an SRE or Cloud Engineer working with enterprise AI workloads, you know that provisioning unified search engines like Gemini Enterprise Search (powered by Vertex AI Search / Discovery Engine) isn't just a simple UI toggle.

When deploying across different corporate environments, you encounter a maze of identity federation options, license SKU assignments, dynamic IAM mappings, and secret management hurdles. Doing this manually for every new customer or environment means spending hours clicking through GCP Console menus, running ad-hoc scripts, and risking configuration drift.

Today, we are diving deep into how we built an automated, end-to-end Infrastructure-as-Code (IaC) pipeline using Cloud Foundation Fabric (CFF) Terraform modules, a CSV-driven parser engine, and interactive onboarding tooling. Let's get started!

Identity & Provisioning Flows
Every customer lands in one of three identity & provisioning modes, and the pipeline auto-selects the right path from the CSV configuration.
  • Google Workspace Native Identity Flow (GWS Native): For customers operating directly inside Google Workspace or Cloud Identity. Access and licensing are managed via Workspace user accounts, Organizational Units (OUs), and Google Groups.
  • Microsoft Entra ID Federated Identity Flow (OIDC / WIF): For enterprise clients federating external Azure/Entra ID directories into GCP. This flow leverages GCP Workforce Identity Pools and OIDC providers to let users log in with their corporate Microsoft credentials without duplicating accounts.
  • Independent & Hybrid Provisioning Mode: Not every customer needs a brand-new project or a full stack. Our setup supports selective execution—allowing you to target an existing GCP project (create_project = FALSE), skip WIF if already configured (provision_wif = FALSE), or deploy only the Gemini search datastores (provision_ai = TRUE).

The Terraform Module Stack

The whole onboarding surface is decomposed into focused, reusable modules that mirror each layer of the stack:
  • project.tf: Handles GCP project creation, billing account linkage, organization association, and API service activation (Discovery Engine, Secret Manager, Cloud Build).
  • iam.tf: Configures Workforce Identity Federation (Entra ID OIDC pool & provider) and assigns organization/project-level administrative IAM roles.
  • ai.tf: Provisions the Gemini Search Engine, sets up datastores (Google Workspace or Microsoft Outlook), configures Access Control Lists (ACLs), user store settings, and embeds the web application search widget.
  • cicd.tf: Sets up remote Terraform state GCS buckets, Secret Manager secret vaults, and Cloud Build v2 triggers connected directly to GitHub repositories.
  • config.tf & config.csv: The engine's heart. A native Terraform parser reads parameters from config.csv to dynamically enable or disable modules and inject runtime variables.
  • script.sh & activate_trial.py: Interactive CLI helper scripts that prompt the user, build the CSV configuration, validate inputs, and verify API/license activation status.

The 4 Pitfalls We Solved
No enterprise automation ships without battle scars. Here are the four hardest problems we hit—and how we engineered around them.

1. Eliminating Secret Casing Mangles in CSV Parsers
  • The Problem: Standard Terraform lowercasing transformations during CSV parsing altered the case of sensitive credentials (such as Azure Client Secrets or GitHub Personal Access Tokens). This resulted in authentication failures like 401 Bad Credentials during Cloud Build setup.
  • The Solution: We updated our native parser in config.tf to selectively process inputs: boolean variables are normalized to lowercase, while security secrets retain their exact literal casing.

2. Overcoming Secret Manager Write-Only Caching
  • The Problem: Because Secret Manager secrets are write-only resources, Terraform does not automatically detect when a token string updates inside a secret payload unless the version tag map changes.
  • The Solution: We implemented explicit version tag key mappings inside cicd.tf. To force an update to an updated token, we increment the version tag identifier (e.g., from v2 to v3), triggering clean Secret Manager version rotation without state corruption.

3. Handling Duplicate Workforce Identity Pools Across Organizations
  • The Problem: Workforce Identity Pools require globally unique identifiers per GCP organization. If a previous setup failed or left a lingering pool, redeploying failed with "Resource Already Exists".
  • The Solution: We added dynamic naming parameterization (workforce_pool_name) inside config.csv and created validation routines in script.sh to check for pre-existing pools before initiating deployment.

4. Bypassing Re-authentication Failures in Multi-Tenant Environments
  • The Problem: Organization-level operations (like WIF provisioning or billing linkages) frequently failed when standard application credentials lacked organization admin privileges.
  • The Solution: The deployment pipeline enforces pre-execution authentication checks, ensuring developers explicitly execute both gcloud auth login and gcloud auth application-default login before provisioning org-level assets.

Licensing: Product & SKU IDs
Correct SKU assignment is what actually turns the search engine on for real users. The pipeline validates these against the customer's billing account:

Quickstart: Spin Up an Environment

Option A: Fully Interactive Helper Script (Recommended) 
chmod +x script.sh
./script.sh
The script guides you through interactive prompts, auto-detects existing values, generates your config.csv, and executes Terraform steps in sequence.

Option B: Manual Terraform Execution
Copy config.csv.example to config.csv and update parameters.

Initialize and target project creation first: 
terraform init
terraform apply -target=module.project -auto-approve
Complete the rest of the stack: 
terraform apply -auto-approve

Automating Gemini Enterprise Search onboarding turns a fragile, click-driven chore into a repeatable, audit-ready pipeline. CSV-driven Terraform with selective module execution keeps every environment reproducible—and the parser hardening we did around secrets, write-only caching, WIF pool naming, and auth pre-checks is exactly the kind of sharp edge you only find by shipping to real multi-tenant enterprises.
